# 32. Лицензии и безопасные умолчания (§60–61)

Два правила, которые действуют для каждого движка — первопартийного и стороннего:

1. **«Лежит на GitHub» ≠ «можно использовать».** Лицензия проверяется явно, а непроверенная
   лицензия считается запрещающей, а не разрешающей.
2. **Новая интеграция по умолчанию выключена**, пока не пройдены четыре проверки: совместимость,
   безопасность, лицензия, здоровье апстрима.

## 32.1 Классификация лицензий (§60)

`packages/integrations/src/license.ts` — небольшая проверяемая таблица SPDX-идентификаторов.
`classifyLicense(declared)` возвращает:

| поле                       | что означает                                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `category`                 | permissive / weak-copyleft / strong-copyleft / network-copyleft / source-available / non-commercial / proprietary / unknown |
| `commercialUse`            | `yes` / `conditional` / `no` / `unknown`                                                                                    |
| `attributionRequired`      | нужно ли переносить copyright-уведомление в дистрибутив                                                                     |
| `redistributionRestricted` | есть ли обязательства сверх атрибуции при включении кода в дистрибутив                                                      |
| `note`                     | одно действие для ревьюера                                                                                                  |

Важные решения таблицы:

- Запуск неизменённого апстрим-контейнера **как отдельного процесса** и **включение его кода в наш
  дистрибутив** — разные действия. GPL-2.0/3.0 помечены `conditional`: запускать можно, линковать и
  вкладывать код — нет.
- AGPL-3.0 — `network-copyleft`: сетевое использование может требовать раскрытия исходников, поэтому
  включение возможно только после явного юридического решения.
- SSPL-1.0, BUSL-1.1, Elastic-2.0, CC-BY-NC-\* — `commercialUse: 'no'`.
- Составные выражения (`MIT OR Apache-2.0`) намеренно **не парсятся**: это решение человека.
- Пустая или незнакомая лицензия → `unknown` + `commercialUse: 'unknown'`, то есть блокировка.

Проверка встроена в conformance-харнесс (`testkit`, правило `license-known`): манифест с
непроверенной лицензией не проходит тест соответствия, а значит не попадает в production registry.

**Зависимости.** Лицензии npm-зависимостей проверяются отдельно, в CI-шаге `audit`; данный документ
описывает лицензии _движков_ (внешних инструментов и их образов). UNVERIFIED: сводного отчёта по
лицензиям транзитивных зависимостей пока нет — это отдельная задача.

## 32.2 Безопасные умолчания (§61)

`packages/integrations/src/safeDefaults.ts` → `evaluateSafeDefaults(manifest)` возвращает
`{ enabledByDefault, blockers[], license }`. Блокировки (все сразу, а не по одной):

| проверка        | блокирует, если                                                                            |
| --------------- | ------------------------------------------------------------------------------------------ |
| `compatibility` | `manifestVersion` не текущая; `maturity` = `experimental` или `deprecated`                 |
| `security`      | запрошены `net:broad` или `files:write`; манифест заявляет `consent.required: false`       |
| `license`       | `commercialUse !== 'yes'` (включая `unknown`)                                              |
| `health`        | `upstreamMaintenance` = `unmaintained`/`unknown`; `risk.label: 'high'` без `risk.fallback` |

Вердикт становится **умолчанием** `enabledForOrg` в реестре. Явный резолвер источника (то есть
решение оператора) по-прежнему важнее: гейт не запрещает включение, он запрещает включение
_молчаливое_. Причины блокировки лежат в `RegistryEntry.safeDefaults.blockers` и показываются в
Admin → Integrations дословно (U5).

### Текущее состояние встроенных движков

| движок            | лицензия   | по умолчанию | причина                                 |
| ----------------- | ---------- | ------------ | --------------------------------------- |
| `expand-url`      | Apache-2.0 | включён      | —                                       |
| `github`          | Apache-2.0 | включён      | —                                       |
| `spiderfoot`      | MIT        | включён      | —                                       |
| `spiderfoot-scan` | MIT        | включён      | —                                       |
| `sherlock`        | MIT        | **выключен** | запрашивает `net:broad` (сотни доменов) |

Sherlock — ровно тот случай, ради которого гейт написан: инструмент опрашивает произвольные сайты,
поэтому его включение должно быть осознанным действием рабочего пространства, а не следствием
установки.
